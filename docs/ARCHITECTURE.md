# SwiftWave — Architecture

## Overview

SwiftWave is a privacy-first, offline peer-to-peer file sharing application.
Files transfer **directly** between nearby devices with no internet, cloud, accounts,
or external storage required.

## Module Responsibilities

### `core/swiftwave_core`

| Module | Responsibility |
|--------|---------------|
| `identity` | Generate and manage device X25519 keypairs. Derive stable `DeviceId`. |
| `discovery` | Trait for peer discovery. Pluggable backends (mDNS, Wi-Fi Aware, BLE). |
| `security` | Noise_XX handshake. AEAD cipher selection (ChaCha20-Poly1305 / AES-GCM). |
| `transport` | Trait for multiplexed byte streams. Primary target: QUIC via `quinn`. |
| `file_engine` | File chunking (256 KiB default), BLAKE3 hashing, transfer state machine, optional Zstd compression. |
| `storage` | Platform-agnostic file I/O trait. `LocalStorage` wraps `tokio::fs`. |
| `platform` | `PlatformAdapter` trait: selects correct discovery + transport backend at runtime. |
| `error` | Unified `SwiftWaveError` enum covering all subsystem failures. |

### `packages/swiftwave_ffi`

Thin `extern "C"` boundary. No business logic. Owns the Tokio runtime.
Exposes: init/shutdown lifecycle, device ID generation, discovery start/stop,
file send/receive (Phase 2). C header auto-generated by `cbindgen` (Phase 2).

### `apps/flutter_app`

| Layer | Package | Responsibility |
|-------|---------|---------------|
| Routing | `go_router` | Declarative, type-safe navigation |
| State | `flutter_riverpod` | Reactive state, auto-dispose, compile-time safety |
| FFI | `ffi` + `swiftwave_ffi.dart` | Bridge to Rust cdylib |
| Theme | Material 3 + `google_fonts` | Consistent, adaptive UI |

### `native/`

Platform-specific code called from Kotlin (Android) or compiled into the
Rust platform adapter crate (desktop). Implements `SwiftWaveDiscovery` /
`PlatformAdapter` using OS-native APIs.

## Data Flow — File Send

```
User picks file
      │
      ▼
Flutter UI → Riverpod provider
      │
      ▼ Dart FFI
swiftwave_ffi::swiftwave_ffi_send_file(peer_id, path)
      │
      ▼
swiftwave_core::FileEngine::prepare_offer(path)
   → compute chunk_count, BLAKE3 hash
      │
      ▼
swiftwave_core::Transport::connect(peer_address)
   → QUIC connection established
      │
      ▼
swiftwave_core::SecurityHandshake::complete()
   → Noise_XX handshake
   → ChaCha20-Poly1305 session
      │
      ▼
swiftwave_core::FileEngine::send_file(offer, path, stream, on_progress)
   → chunk loop: read → [compress] → encrypt → send
      │
      ▼
Flutter UI receives progress events via callback / channel
```

## Security Design Principles

1. **No trust in transport** — Noise_XX provides authentication and encryption
   independently of QUIC's TLS layer. Defence in depth.
2. **Trust-on-first-use (TOFU)** — device public keys are pinned after the
   first successful handshake.
3. **No metadata to servers** — no telemetry, no analytics, no crash reporting.
4. **Ephemeral sessions** — session keys are derived fresh per connection.
   Compromise of a session key does not affect past or future sessions.
5. **Key isolation** — private keys never leave the secure storage boundary
   (Android Keystore, macOS Keychain, Windows DPAPI).

## Performance Targets

| Metric | Target |
|--------|--------|
| App binary size | < 15 MB (release, stripped) |
| Idle RAM (Rust core) | < 5 MB |
| Transfer CPU overhead | < 5 % on a 2-core device at 100 MB/s |
| Transfer throughput | Saturate available Wi-Fi bandwidth |
| Startup time | < 1 s cold start on mid-range devices |
